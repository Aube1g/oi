## Потокобезопасность `LayerStore`

Закрыл последний пункт TODO. Раньше `commit()`/`set_ref()`/`add_tag()`/
`attach_file_writes()` читали `self._index`/`self._refs` из памяти (загруженных
один раз при создании `LayerStore`), мутировали и писали JSON-файл целиком —
классический lost-update race между несколькими процессами/потоками на одном
`root`.

Фикс — оба обязательных условия:
1. **`fcntl.flock`** (POSIX) на файл `.lock` в корне стора вокруг каждой
   мутации.
2. **Пере-чтение `index.json`/`refs.json` с диска ПОСЛЕ захвата лока, ПЕРЕД
   мутацией** — без этого лок бесполезен: устаревшая копия в памяти всё равно
   перезапишет то, что успел закоммитить другой процесс, пока текущий ждал
   лок.

На Windows (`fcntl` недоступен) деградирует до best-effort без
кросс-процессной защиты — задокументировано в докстринге `_locked()`,
предложена `portalocker` как кросс-платформенная альтернатива, если это
когда-нибудь понадобится на Windows в multi-process сценарии.

**Проверено реальной конкуренцией**: 5 отдельных Python-процессов
(`subprocess.Popen`, не потоки — это by design, чтобы проверить именно
кросс-процессный случай, не просто GIL-защищённые потоки) по 20 коммитов
каждый в один и тот же `root` параллельно → все 100 коммитов на месте,
ни один не потерян. Новый `tests/test_layers_concurrency.py`.

# Проход 4 — единая точка входа: AutonomyMode

Закрыл третий пункт TODO. Раньше `enable_self_correction` (флаг на
`run_chain()`) и `IdleReconciler` (отдельный класс, который вообще нигде не

`IdleReconciler` фактически был мёртвым кодом без диспетчера.

## `AutonomyMode` (в `chain.py`)

Три уровня на `XliCore(..., mode=...)`:

- **MANUAL** (дефолт, старое поведение без изменений) — self-correction
  выключен если явно не передан `enable_self_correction=True`, idle-реконсиляция
  не запускается сама.
- **ASSISTED** — self-correction включается автоматически (реальный
  pytest-цикл DEBUGGER↔TESTER вместо одного слепого прохода), но
  idle-реконсиляция всё ещё требует ручного управления — полезно, если
  какой-то внешний event loop (например UI) уже сам решает, когда простой.
- **AUTONOMOUS** — оба рычага включены. `XliCore` теперь сам владеет
  `self.reconciler` (`IdleReconciler`) и гоняет его вокруг каждого вызова
  `run_chain()`: проверка `maybe_run()` в начале вызова (до старта цепочки),
  затем `note_activity()` в конце. Порядок специально такой — проверка в
  начале следующего вызова видит реальный разрыв между двумя вызовами
  `run_chain()` (человек отошёл, очередь простаивает); проверка в конце
  того же вызова почти никогда бы не сработала, т.к. сам прогон цепочки
  занимает меньше времени, чем `idle_threshold_seconds` — это измеряло бы
  время работы цепочки, а не реальный простой.

`enable_self_correction` теперь `Optional[bool] = None` — если не передан
явно, решается по `mode`; если передан явно (`True`/`False`), всегда
побеждает над `mode`, так что старые вызовы с явным булевым флагом ведут
себя ровно как раньше.

`self.reconciler` создаётся всегда (дёшево — ни потоков, ни I/O до
`maybe_run()`), доступен и в MANUAL/ASSISTED для ручного управления.

Проверено вручную и тестами: реальный разрыв в 0.3с между двумя вызовами
`run_chain()` в AUTONOMOUS корректно ловится и запускает реконсиляцию;
первый вызов (без предыдущей активности) — нет. 6 новых тестов в
`test_chain.py`. `tests/test_xli.py` по-прежнему 22/23, регрессий нет.

**Осталось по списку**: слияние `layers.py`/`memory.py` для контекста
`XliAgent.think()`, потокобезопасность `LayerStore`. UI (`headless.py`,
`tui.py`) намеренно не тронут — оба продолжают создавать `XliCore` без
`mode=` (остаются MANUAL), подключение флага в CLI — отдельная задача,
не багфикс.

# Проход 3 — checkout() + сквозной тест run_chain()

Закрыл первые два пункта из TODO-списка предыдущего прохода.

## `LayerStore.checkout(layer_id)` — восстановление реального состояния файлов

Раньше слои (`layers.py`) хранили только *текст ответа агента* — не то, что
реально оказалось на диске. Путь `<tool>write</tool>` парсился и исполнялся
отдельным шагом (`_process_tools` в `chain.py`), уже после того как слой
для этого ответа был закоммичен, и путь/контент нигде не привязывался к
layer_id. `checkout()` без этой привязки был невозможен в принципе.

- `LayerMeta.file_writes` (новое поле, `List[Dict]`, дефолт `[]`) — какие
  реальные файлы проекта этот слой записал, с отдельным хранением контента
  и хешем на файл. Обратно совместимо: старые `index.json` без этого поля
  загружаются нормально (проверено тестом).
- `LayerStore.commit(..., file_writes={path: content})` — коммит слоя сразу
  с привязкой файлов (используется в `self_correcting_chain.py`).
- `LayerStore.attach_file_writes(layer_id, {...})` — привязать file_writes
  к уже существующему слою постфактум (используется в `chain.py`, т.к. там
  запись файлов происходит отдельным шагом после коммита).
- `LayerStore.checkout(layer_id, dest_root=None, dry_run=False)` — идёт по
  цепочке родителей от `layer_id` к корню, реплеит file_writes в хронологическом
  порядке (последняя запись по каждому пути побеждает — как git). Без
  `dest_root` пишет в реальные пути проекта (настоящий checkout); с
  `dest_root` — в сторону, для безопасного просмотра; `dry_run=True` вообще
  не трогает диск.
- `Reconciler.checkout_best()` — обёртка: находит лучшую `"working"`-версию
  через `find_best()` и восстанавливает её. Это то самое "откатиться",
  которого не хватало — сценарий "файл испортили извне → откатить на
  последнюю рабочую версию" теперь реально работает и покрыт тестом.
- `self_correcting_chain.py`: вместо попытки распарсить путь из текста
  ответа агента, после каждой попытки CODER/DEBUGGER снимается снапшот
  реального содержимого `target_file` с диска — надёжнее, чем парсинг.
- `chain.py`: `_do_write`/`_do_edit` теперь возвращают `(path, content)`,
  `_process_tools` собирает их за шаг и вызывает `attach_file_writes` —
  все 6 шагов `run_chain()` теперь привязывают свои файлы к своим слоям.

Тесты: 7 новых в `test_layers.py`, 3 новых в `test_reconciler.py`.

# Слоистый контекст + self-correcting loop (3-й проход)

## Новое

20. **`xli/core/layers.py`** (новый) — `LayerStore`: git-commit-style версионирование
    контекста. Каждый значимый шаг (план/код/результат теста/фикс) коммитится как слой:
    - `note` (короткая заметка) живёт в дешёвом JSON-индексе — это то, что реально
      скармливается модели как контекст
    - `content` (полное) пишется файлом на диск один раз, в индексе — только путь + sha256
    - `get_full()` **всегда** пересчитывает хэш файла и сверяет с тем, что записан в
      индексе — если заметка разошлась с реальностью (файл поменяли в обход стора),
      это явно ловится (`verified: False`), а не тихо доверяется устаревшей заметке
    - `history()` — обход по parent-цепочке (как `git log`), `diff()` — unified diff
      между двумя версиями (переиспользует существующий `diff_engine.py`)
    - `refs` — именованные указатели (`HEAD`, `last_good`) как git branches/tags
21. **`xli/core/goal.py`** (новый) — `Goal`: явная, проверяемая цель вместо "прогнали
    N шагов и остановились". Список `Criterion` (описание + callable-проверка),
    `max_iterations`, `attempts` — каждая попытка хранит только `layer_id` (доказательство
    в LayerStore), не дублирует контент.
22. **`xli/core/self_correcting_chain.py`** (новый) — реальный цикл
    CODER → TESTER → DEBUGGER → TESTER → ... :
    - TESTER **реально запускает pytest** через `exec_guard.run_guarded_shell()`
      (не спрашивает LLM "выглядит ли код правильно")
    - Результат теста коммитится как слой: note = "3 failed, 2 passed" (компактно),
      full = весь pytest-вывод (по требованию)
    - DEBUGGER получает note + diff против `last_good`, не полный traceback — если
      этого не хватит, полный лог всегда доступен через `get_full(layer_id)`
    - Останавливается, как только `Goal` выполнен, а не после фиксированного числа шагов
    - `last_good` ref двигается **только** когда тесты реально прошли

## Проверено вручную (E2E, без сети/API-ключей)

Прогнал полный цикл на `FakeProvider`: CODER пишет баг (`a - b` вместо `a + b`) →
TESTER ловит fail → DEBUGGER получает note + diff → чинит → TESTER подтверждает pass →
цикл останавливается на 2-й итерации из 4 доступных. Отдельно проверил:
самопроверку (руками испортил файл слоя в обход store → `get_full()` поймал
расхождение хэша), `last_good` действительно указывает на прошедшую версию.

Написаны pytest-тесты: `tests/test_layers.py`, `tests/test_goal.py`,
`tests/test_self_correcting_chain.py` (последний — интеграционный, с exec-based
стендом вместо реального pytest, чтобы не зависеть от subprocess в CI-песочнице).
В этой sandbox нет сети для `pip install pytest`, поэтому тесты прогнаны напрямую
(без pytest-раннера) — логика идентична, синтаксис/декораторы для реального
pytest корректны и отработают в GitHub Actions.

## Не сделано / на следующий проход

- **Цепочка агентов в целом не переписана** — `SelfCorrectingChain` пока отдельный
  модуль поверх `XliAgent`/`exec_guard`, не встроен в `XliCore.run_chain()` как
  замена линейного CODER→TESTER→DEBUGGER. Нужно решить: заменить существующий шаг
  в `chain.py` целиком или сделать флагом ("use_self_correction: true" в конфиге).
- **PLANNER/OPTIMIZER/REVIEWER не коммитят слои** — только CODER/DEBUGGER/TESTER
  в новом цикле. Чтобы "заметки вместо всей истории" работало для всего chain, а
  не только для code-fix цикла, нужно завести layer-коммиты на каждом шаге основного
  `XliCore.run_chain()`.
# Встраивание в XliCore + Reconciler простоя (4-й проход)

## Встраивание слоёв в основную цепочку

23. **`XliCore.run_chain()` теперь коммитит слой на каждом из 6 шагов**
    (PLANNER/CODER/DEBUGGER/TESTER/OPTIMIZER/REVIEWER), не только code-fix цикл.
    История всего прогона доступна как `store.context_window()` — компактные
    заметки, не полные ответы. По завершении `last_good`/`last_chain_run` ref
    двигается на последний слой в зависимости от `result.success`.
24. **Новый флаг `run_chain(..., enable_self_correction=True)`** — заменяет
    "слепой" разовый DEBUGGER на реальный цикл `SelfCorrectingChain` из
    прошлого прохода: после того как TESTER написал тестовый файл, код
    реально прогоняется через pytest и DEBUGGER крутится, пока тесты не
    пройдут (или не кончится `max_correction_iterations`). По умолчанию
    выключено — старое поведение не ломается.

## Найдено и исправлено (случайно, при первом реальном прогоне run_chain)

Раньше `run_chain()` никогда не тестировался end-to-end (юнит-тесты проверяли
только структуру `core.agents`, не реальный прогон). Как только я прогнал его
по-настоящему, всплыли **два бага, из-за которых метод не мог доработать даже
до конца первого шага**:

25. **`self.env.project_dir` не существовал** — `EnvironmentAdapter` (env.py)
    имел только `.cwd`. 4 места в `chain.py` падали с `AttributeError` при
    первом же обращении. Добавил `self.project_dir = self.cwd` как алиас.
26. **`self.memory` не существовал на `XliCore`** — `_run_agent()` дергал
    `self.memory.save_conversation(...)` на каждом шаге, но `XliCore.__init__`
    никогда не создавал `self.memory`. Добавил `self.memory = get_memory()`.

Это означает: `run_chain()` в этом проекте **никогда не отрабатывал
end-to-end ни разу**, с самого начала. Только сейчас, когда я реально его
прогнал (проверяя интеграцию слоёв), это вскрылось.

## Reconciler простоя (`xli/core/reconciler.py`, новый)

То, что просили отдельно: механизм, который в неактивное время сверяет
заметки с реальными файлами и выбирает лучшую рабочую версию.

- **`verify_all()`** — проходит по ВСЕМ слоям в сторе, пересчитывает хэш
  каждого файла, возвращает отчёт (сколько разошлось / пропало). Массовая
  версия той же проверки, что `get_full()` делает для одного слоя.
- **`find_best()`** — не "самая новая версия", а **самая новая версия,
  реально помеченная `working`** (т.е. чьи тесты прошли по-настоящему).
  Фолбэк: ref `last_good`, потом `HEAD`.
- **`consolidate()`** — старые невостребованные слои (не в последних N, не
  под именованным ref'ом, не тегированы `working`) **архивируются, не
  удаляются**: файл переезжает в `archive/`, запись в индексе остаётся,
  `history()`/`diff()`/заметки продолжают работать, `get_full_anywhere()`
  находит содержимое и там, и там же ловит порчу файла хэшем.
- **`IdleReconciler`** — гейтинг по простою без внешних зависимостей:
  `note_activity()` вызывается при реальной работе агента, `maybe_run()`
  дергается периодически (из UI-луп/cron/systemd-таймера) — реально
  запускает verify+consolidate только если прошло >= `idle_threshold_seconds`
  с последней активности, и не дублирует прогон без новой активности после
  предыдущего.
- `LayerMeta.tags` теперь используется по-настоящему: `self_correcting_chain.py`
  тегирует code-слой `"working"` в момент, когда его тест реально прошёл
  (`store.add_tag(code_layer, "working")`), а не просто по факту "последний".

**Проверено вручную**: 5 версий кода закоммичены, только последняя помечена
`working` — `find_best()` возвращает именно её, а не просто HEAD. 10 старых
скретч-слоёв — `consolidate(keep_recent=3)` архивировал 11 (всё кроме working
+ 3 последних), архивный слой остался читаемым и самопроверяемым, тампер
архивного файла пойман. `IdleReconciler` не срабатывает раньше порога и не
дублирует запуск без новой активности. Плюс `tests/test_reconciler.py`
(7 тестов, все зелёные при прямом прогоне без pytest-раннера).

## Всё ещё не сделано

- **PLANNER/OPTIMIZER/REVIEWER коммитят слои, но не тегируются и не
  участвуют в self-correction** — `enable_self_correction` затрагивает
  только CODER/DEBUGGER/TESTER-часть. Reviewer, например, мог бы тоже иметь
  критерий Goal ("review approved") со своим циклом правок.
- **IdleReconciler ничего не запускает сам** — это гейтинг-примитив, кто-то
  снаружи должен реально дёргать `maybe_run()` по таймеру/из event loop UI.
  Не стал добавлять systemd/cron юнит — зависит от способа деплоя.
- **`consolidate()` не потокобезопасен** так же, как и сам `LayerStore`
  (см. пункт про file lock из прошлого прохода) — не гонять параллельно
  с активным `commit()` из другого процесса без лока.

## 1. Что сделано

### Безопасность (пункт 2 из плана)

Было три списка запретов — в `permissions/policy.py`, в `core/shell_safety.py`
и в `nvim`-мосте. Они разошлись: один знал про `dd of=/dev/*`, другой нет, и
какой срабатывал, зависело от того, кто первый вызвал проверку.

* `xli/core/shell_safety.py` — **единственный** список правил. Команда режется
  на сегменты (`;`, `&&`, `||`, `|`, `&`, перевод строки), с каждого снимаются
  обёртки (`sudo`, `env`, `nohup`…), после чего каждый сегмент проверяется
  отдельно. `ls; dd if=… of=/dev/sda` больше не «команда, начинающаяся с `ls`».
* Кавычки больше не прячут команду: `rm -r"f" /` блокируется.
* Новое: `cd / && rm -rf *`, `rm -rf /<системный каталог>`, `dd of=/dev/*`,
  `base64 … | sh`, `find / -delete`, `git push --force`, `git reset --hard`,
  `kill -9 -1`, fork bomb.
* `sudo` — подтверждение для обычной установки, отказ для разрушительных команд.
* Данные больше не путаются с командами: `git commit -m "fix: убрал rm -rf /"`
  проходит, а `echo 'rm -rf /' > notes.txt` — обычная запись файла.
* `Policy` проверяет **все** ресурсы вызова, а не первый найденный
  (`path` + `command` раньше судили по `path`, и правило про команду не срабатывало).
  Списки аргументов разворачиваются.
* Запись вне корня проекта — эскалация в любом режиме (`check_path_inside_root`
  существовала, но её никто не вызывал).
* `xli permissions show | check ТУЛ [--args JSON] | log` — политику можно
  спросить, не выполняя ничего.
* 55 новых тестов: `tests/test_security_hardening.py`.

### Графы (пункт 9)

`xli graph` больше не печатает ёлочку из имён импортов и не использует эмодзи.
Вопрос, на который он отвечает, — «за что можно дёрнуть и что дёрнет за собой»:

* `xli graph` — обзор: на чём держится проект, точки входа, циклы;
* `xli graph ИМЯ` — что тянет модуль за собой; `--reverse` — кто тянет его;
* `xli impact ФАЙЛ` — прямое влияние, цепочка, зависимости, **тесты, которые его
  упоминают**; это и есть ответ «что сломается, если тронуть»;
* `--json` для машинной обработки.

Важное для честности картины: циклы считаются только на уровне модуля.
Импорт внутри функции циклом не является (модуль уже загружен), и такие рёбра
помечены отдельно — `DependencyGraph.deferred` (311 рёбер), а настоящих
циклов в проекте **ноль**.

### TUI (пункты 1, 5, 6)

TUI выглядел рабочим, но **не работал**:

1. `xli tui` не создавал ни провайдера, ни реестра, ни политики — каждая задача
   заканчивалась `AttributeError: 'NoneType' object has no attribute 'chat'`.
2. Цикл событий не отдавал управление: `run_async` опрашивал клавиатуру без
   `await`, поэтому задача агента, созданная на этот ход, не выполнялась.
3. `^C` в терминале — это сигнал, а не клавиша; внутри работающего цикла он
   проглатывался, и процесс оставался живым с мёртвым интерфейсом.
4. Логи писались в `stderr`, то есть **поверх собственного кадра**: отсюда
   рваные строки и обрывки «initialized» посреди интерфейса.

Плюс:

* кадр с рамкой: заголовок с провайдером/моделью/сессией и пульсом, полоса
  состояния, низ — строка статуса на всю ширину;
* панели по `Tab` (план → граф → агенты → статистика), `1..4` — выбрать,
  `Esc` — закрыть, `/plan` `/graph` `/agents` `/stats`;
* у каждого субагента свой цвет (по имени, стабильный) и своё имя в строке —
  «в один цвет» больше не выглядит;
* побайтовое чтение клавиатуры: `Esc` закрывает панель всегда, стрелки не
  печатаются как `[A`, кириллица не превращается в мусор;
* панель «статистика» рисует время по шагам (braille-график) и топ инструментов;
* панель «граф» считает граф в отдельном потоке, показывая «считаю…».

## 2. Что осталось

По исходному порядку задач:

1. **Правки из аудита.** Файл `audit.md` пропал при переинициализации
   репозитория (он никогда не был в git). Если он у вас сохранился — пришлите,
   сверю остаток списка. Из известного: цикл импортов задокументирован
   (`deferred`), `BUILD_TOOLS` пришпилен тестом, тесты-заглушки переписаны.
2. **Инструменты** — из плана не сделаны: `find_symbol`, `check_imports`,
   `py_eval`, `api_schema`.
3. **MCP** — не начато: менеджер серверов, форматы `.mcp.json` и Codex-TOML,
   `enabled_tools`/`disabled_tools`, таймауты, статус серверов в CLI и TUI.
4. **Анимации** — есть (градиентная рамка, бегущий блик в разделителях,
   спиnнер, пульс в заголовке), но CLI-анимации прогона задачи ещё скромные.
5. **Стрелки между задачами в плане** — метки (`✓ ◐ ☐ ✗`) есть, стрелок
   зависимостей `├─ ▸` / `└─ ▸` пока нет.
6. **Вывод сборки ядра** — не украшался (пункт 8).
7. **Графы в обычной работе** — CLI и панель TUI готовы; не сделано:
   показывать влияние автоматически, когда агент правит файл.
8. **Сквозной ретро-обзор** нового кода на конфликты (пункт 10) — не начат.
9. Цвета в 256-цветном TUI для `#RRGGBB`-стилей субагентов реализованы через
   динамические пары; на 8-цветном терминале они деградируют до обычного.

## 3. Как проверять

```bash
python3 -m pytest -q                 # весь набор
python3 -m xli demo                  # витрина рендереров
python3 -m xli demo animate          # анимация заголовка
python3 -m xli graph                 # обзор графа
python3 -m xli impact xli/cli.py     # что сломается при правке
python3 -m xli permissions show      # действующая политика
python3 -m xli tui --provider fake   # TUI без сети и ключей
python3 scripts/tui_probe.py --cols 100 --rows 24 -- python3 -m xli tui --provider fake
```

`pip install --break-system-packages pytest pyte httpx python-dotenv pytest-asyncio pyyaml`
— зависимости окружения сбрасываются между сессиями.
